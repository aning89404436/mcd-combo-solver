## 三、方案：长周期营养顾问

### 一句话定位

> 不是「帮你省 20 块钱」，而是「帮你在麦当劳吃三个月不崩」。

### 三个差异化支点

**支点一 · 周期饮食状态机**

同一个麦麦套餐，在不同状态下给出不同策略：

| 状态 | 策略侧重 |
|---|---|
| 平时 | 均衡、口味优先 |
| 减脂期 | 蛋白密度最大化、隐藏酱汁、零糖饮料替换 |
| 增肌期 | 热量余量优先、碳水补偿 |
| 加班/ 熬夜 | 控钠控脂、低 GI、不给胃负担 |

别人是「一次性推荐」，我们是「有状态记忆的陪伴」。

**支点二 · 预算 × 营养双约束求解**

- 不是「最便宜」，是**每 100 元的蛋白质克数最大化**
- 本地`combo_solver.py` 先枚举「主餐 × 小食 × 饮品」全组合
- 按热量 / 蛋白 / 钠预算过滤出 Top-K
- 只对候选调`calculate-price` —— **这是限流下的必然取舍**
  （Token 限流 600 次/分钟，全交给模型试错一局就见底）

**支点三 · 本地化 + 视觉化**

- 云南门店实际菜单可得性
- 你的设计能力做成的营养可视化（别人没有的）

### laoning 的独有优势

| 优势 | 具体用在哪 |
|---|---|
| 设计 / 建筑背景 | README 首屏视觉、GIF、信息图 —— 直接影响 star 转化率 |
| 营养学积累 | DRIs 口径、克数核算、营养密度判断，已有验证过的方法论 |
| 昆明在地| 门店可得性、本地饮食习惯 |

## 四、已知的坑（官方 README + 实战教程共同证实）

| 坑 | 说明 | 应对 |
|---|---|---|
| `list-nutrition-foods` 返回 TOON 文本 | 不是 JSON。首行字段定义头；数据行的值可能为 null 或自带逗号，**不能按固定位置 split(',')** | 必须写 `toon_parser.py` |
| 价格单位不一致 | `query-meals` 返回「元」且通常是字符串；`calculate-price` 返回「分」 | 展示层除以 100 |
| 套餐替换限制 | 替换只能发生在**同一 round 的候选项**里 | 候选枚举时锁定 round |
| 去酱 / 同轮零加价替换 | 去酱走 `modification`；可乐换无糖是同轮零加价 | 明确区分两类 |
| 到店自取 | `beType=1`，后续调用不用重复传 `beCode` | |
| 限流 | 600 次/分钟，超限 429；401 = token 无效/过期 | 本地先算，别硬试错 |
| Token 安全 | Token 等于麦当劳会员账号钥匙 | 严禁进仓库、严禁进截图，只用环境变量占位符 |

## 五、合规红线（这条比技术重要）

规则原文明确禁止：

1. **「将麦当劳品牌、产品与其他品牌、产品进行对比」**
   → 省钱类项目最容易被抓。别做「麦当劳 vs 肯德基/汉堡王」
2. **「宣扬不健康饮食方式」**
   → 别说「这么吃能减肥」。合规表述：**营养信息辅助参考，不构成医疗建议**
3. 政治敏感内容、赌博/迷信内容（塔罗类项目其实踩在雷上）
4. `CONTEST_DECLARATION.md` 的文件名和内容**都不许改**
5. Token 泄露、植入恶意脚本

还有一条容易忽略：**麦当劳会把参赛者 GitHub 账号与麦当劳会员账号关联**，用于核验身份。所以不要用主账号随便注册。
